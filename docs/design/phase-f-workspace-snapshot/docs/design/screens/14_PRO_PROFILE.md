# پروفایل عمومی متخصص — /pro/profile

مسیر: `/pro/profile`

## هدف
ساخت/ویرایش پروفایل عمومی و ارسال درخواست احراز هویت.

## کاربر و زمینه
نیاز به نقش bc_provider.

## وابستگی API
createProvider، updateProvider، listCities، listSpecialties، submitVerification، myVerification؛ رسانه (فاز C): POST /v1/media/upload-url، POST /v1/media/:id/finalize، POST /v1/providers/:id/portfolio، DELETE /v1/providers/:id/portfolio/:itemId، PATCH /v1/providers/:id/avatar، PATCH /v1/providers/:id/cover، POST /v1/verification/evidence، GET /v1/verification/me/evidence.

## فیلدهای واقعی داده
displayName، bio، cityId، specialtyIds، وضعیت احراز هویت؛ نمونه‌کار: mediaId، caption؛ آواتار/پوشش: mediaId یا null؛ مدرک احراز هویت: mediaId، downloadUrl (پروتکتد، ۵ دقیقه معتبر، هربار بازاعتبارسنجی می‌شود).

## چیدمان
فرم دوستونه (نام/شهر/تخصص‌ها + معرفی‌نامه)؛ زیرِ آن بلوکِ تصاویر — دو ناحیهٔ بارگذاری برای آواتار (حداکثر ۴ مگابایت) و پوشش (حداکثر ۸ مگابایت)، سپس نگارخانهٔ نمونه‌کار به‌صورت شبکهٔ کارتِ قابل‌افزودن/حذف (حداکثر ۴۰ مورد)؛ بلوک وضعیت احراز هویت جدا با نشان رنگی، شاملِ فهرستِ مدارکِ ارسالی و دکمهٔ افزودنِ مدرکِ تازه.

## اجزا
Input، Textarea، Select (چندانتخابی برای تخصص)، Badge، Alert

## حالت‌ها
بارگذاری اسکلتی فرم؛ خطا با aria-describedby روی هر فیلد؛ موفقیت با پیام درجا (نه Toast).

## کنش‌ها
ذخیرهٔ پروفایل، ارسال درخواست احراز هویت؛ بارگذاری تصویر در سه گام — درخواست آدرس بارگذاری → ارسال مستقیم بایت‌ها → finalize؛ افزودن/حذف نمونه‌کار؛ تنظیم یا پاک‌کردن آواتار/پوشش (mediaId یا null)؛ افزودن مدرک احراز هویت به درخواست باز.

## قواعد واکنش‌گرایی
۳۹۰: فرم تک‌ستونه؛ ۱۲۸۰: دو‌ستونه.

## قواعد راست‌به‌چپ و فارسی
—

## دسترس‌پذیری
هر فیلد label واقعی؛ خطا role=alert.

## رفتار تعامل
بارگذاری باید پیشرفت (٪) نشان دهد و خطای finalize را با پیام واقعی (حجم بیش از حد، ابعاد کوچک/بزرگ، نوع فایل نامعتبر) نشان دهد، نه پیام عمومی. جایگزینیِ آواتار/پوشش، تصویرِ قبلی را بلادرنگ در پیش‌نمایش عوض می‌کند؛ حذفِ نمونه‌کار تأیید دوم نمی‌خواهد (غیرمخرب و قابل بازگشت با بارگذاریِ دوباره).

## عناصر آینده/شکاف
بارگذاری مدرک، آواتار، پوشش و نگارخانه — دیگر شکاف نیست، IMPLEMENTABLE NOW (فاز C). صفِ بازبینیِ گزارش‌های تصویر نامناسب (bc_moderate_media) یک سطحِ اپراتوری جداست — ۲۷_ADMIN_MEDIA_MODERATION.md.

## یادداشت پیاده‌سازی
وضعیت احراز هویت (در انتظار/تأییدشده/رد‌شده) باید در بالای فرم دیده شود، نه فقط در نتیجهٔ ارسال. آپلود پرسنددایرکت (presigned) است — سرور بدنهٔ فایل را نمی‌بیند؛ finalize اولین لحظه‌ای است که سرور واقعاً محتوا را می‌سنجد، پس خطای اعتبارسنجی همیشه بعد از بارگذاری کامل می‌رسد، نه قبل از آن.
