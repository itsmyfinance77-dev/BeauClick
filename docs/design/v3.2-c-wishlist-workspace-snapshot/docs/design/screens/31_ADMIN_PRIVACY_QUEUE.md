# صفِ حریمِ خصوصی — /admin/privacy

مسیر: `/admin/privacy` (هنوز در apps/web ساخته نشده — فاز E، UI REQUIRED، هم‌شکل با الگوی ۲۸_ADMIN_REVIEW_MODERATION برای صف‌های اپراتوری)

## هدف
نظارتِ صرف بر وضعیتِ درخواست‌های حریمِ خصوصیِ کاربران — سطحی برای پایش، نه برای کنترل. هیچ کنشِ اپراتور نمی‌تواند محتوای دادهٔ کاربری را بخواند یا روندِ حذف را متوقف کند.

## کاربر و زمینه
نیاز به قابلیتِ `bc_manage_platform`، نه یک نقشِ ناظرِ محتوا — این سطحِ عملیاتی/امنیتی است، نه بازبینیِ محتوا.

## وابستگی API
GET /v1/admin/privacy/requests?page=&limit=&status= — فقط همین یک مسیر. **هیچ مسیرِ دیگری در این ناحیه وجود ندارد و نباید در رابط کاربری فرض شود.**

## فیلدهای واقعی داده
id، subjectUserId، kind (`export`|`erasure`)، status، requestedAt، executeAfter، expiresAt، completedAt، cancelledAt، failureCode. همین و نه بیشتر — بدنهٔ سندِ خروجی، شمارهٔ تلفن، یا هر داده‌ای که موضوعِ درخواست است در این پاسخ نیست و هرگز نخواهد بود.

## چیدمان
جدولِ صف با فیلترِ وضعیت (`pending`/`processing`/`ready`/`expired`/`failed`/`cancelled`/`completed`) و نوع (`export`/`erasure`) بالای جدول. ستون‌ها: شناسهٔ موضوع (کوتاه‌شده)، نوع، وضعیت (Badge رنگی)، تاریخِ درخواست، مهلت/انقضا (بسته به نوع)، کدِ خطا (اگر `failed`). کلیکِ ردیف چیزی باز نمی‌کند — این جدول جزئیاتِ بیشتری ندارد که نشان دهد؛ یک بنرِ ثابت بالای صفحه صریحاً می‌گوید: «این صفحه فقط وضعیت را نشان می‌دهد. دانلودِ داده یا لغوِ حذف از اینجا ممکن نیست.»

## اجزا
Table، Badge (وضعیت)، SegmentedControl یا Select (فیلترها)، Alert (info — توضیحِ محدودیتِ صفحه).

## حالت‌ها
بارگذاریِ اسکلتی؛ خالی: «صفی برای نشان‌دادن نیست»؛ خطا با تلاشِ دوباره. **بدون حالتِ موفقیت/خطای کنش** — چون هیچ کنشی روی این صفحه وجود ندارد.

## کنش‌ها
فیلتر بر اساسِ وضعیت/نوع، صفحه‌بندی. هیچ کنشِ دیگری. `failureCode` روی یک ردیفِ `failed` چیزی است که اپراتور می‌خواند و بیرونِ این صفحه (در سیستمِ زیرساخت یا با ارتباط مستقیم) پی‌گیری می‌کند.

## قواعد واکنش‌گرایی
۳۹۰: جدول به فهرستِ کارت تبدیل می‌شود، فیلترها در یک شیت.

## قواعد راست‌به‌چپ و فارسی
تاریخ‌ها شمسی با اعدادِ فارسی؛ `subjectUserId` به‌صورتِ کوتاه‌شده و لاتین (`direction: ltr`) چون شناسهٔ فنی است.

## دسترس‌پذیری
بنرِ محدودیتِ صفحه با `role=note` نه فقط رنگ؛ فیلترها با برچسبِ صریح.

## رفتار تعامل
هیچ دکمهٔ دانلود، هیچ دکمهٔ لغو، هیچ راهی به سندِ کاربرِ دیگر — نه فقط غیرفعال، اصلاً در رابط کاربری وجود ندارد. طراحیِ این صفحه با فرض نبودِ این کنش‌ها انجام شده، نه با پنهان‌کردنِ کنش‌هایی که در نسخه‌ای دیگر بودند.

## عناصر آینده/شکاف
هیچ. این صفحه دقیقاً همانی است که API اجازه می‌دهد — هیچ گسترشی از این سطح در نقشهٔ راه فعلی وجود ندارد، و گسترش‌دادنش (مثلاً افزودنِ لغوِ اپراتوری) یک نقضِ امنیتیِ عمدیِ طراحیِ فاز E خواهد بود، نه یک شکاف.

## یادداشت پیاده‌سازی
بک‌اند کامل و آزموده است (adversarial: یک `platform_operator` نمی‌تواند خروجیِ کاربرِ دیگر را دانلود یا حذفِ او را لغو کند، حتی با نشستِ خودش). مسیرِ فرانت هنوز وجود ندارد.
