# صفحه اصلی — /

مسیر: `/`

## هدف
اولین صفحه‌ای که هر بازدیدکننده می‌بیند؛ باید بگوید بیوکلیک چیست، چطور جست‌وجو و رزرو کار می‌کند.

## کاربر و زمینه
بدون نیاز به ورود. امروز یکسان برای کاربر واردشده و نشده رندر می‌شود.

## وابستگی API
هیچ — امروز صفحه هیچ API صدا نمی‌زند. الف: هیچ؛ ب: شمار متخصص و کمترین قیمت هر تخصص از facets جست‌وجو در بار اول قابل استخراج است.

## فیلدهای واقعی داده
هیچ فیلد زنده امروز رندر نمی‌شود؛ نمونهٔ بصری از facets جست‌وجو استفاده می‌کند.

## چیدمان
قهرمان با جست‌وجوی درون‌خطی؛ ردیف تخصص‌های پرجست‌وجو؛ ردیف متخصص‌های تأییدشده؛ سه‌قدم رزرو؛ پاصفحه.

## اجزا
SearchField، ProviderCard، Button، Badge

## حالت‌ها
بدون حالت بارگذاری/خطا در بار اول (رندر سروری بدون فراخوانی). اگر تخصص‌های پرجست‌وجو از facets آورده شود، حالت بارگذاری اسکلتی و حالت خطا (Alert + تلاش دوباره) لازم است.

## کنش‌ها
جست‌وجو → /search، کلیک تخصص → /search?specialty=، کلیک متخصص → /providers/[id]

## قواعد واکنش‌گرایی
۳۹۰: تک‌ستون، جست‌وجو تمام‌عرض. ۱۲۸۰: قهرمان دو‌ستونه (متن + تصویر جای‌نگهدار)، شبکه ۴ ستونه تخصص‌ها.

## قواعد راست‌به‌چپ و فارسی
جست‌وجو و آیکن جهت‌دار به راست؛ اعداد فارسی؛ قیمت با تومان یک‌بار در هر کارت.

## دسترس‌پذیری
role=search روی جعبهٔ جست‌وجو؛ heading واحد h1؛ کنتراست AA روی تصویر جای‌نگهدار.

## رفتار تعامل
بدون هاور مخفی؛ فوکوس قابل مشاهده روی همهٔ کارت‌ها و دکمه‌ها.

## عناصر آینده/شکاف
تصویر/نمونه‌کار — BACKEND GAP (بدون رسانه). آمار پلتفرم («۵۰۰۰ رزرو») و دیدگاه مشتری — ساخته نشد، این داده مدیریتی است و عمومی نیست.

## یادداشت پیاده‌سازی
امروز 51 خط، بدون API. باید حداقل facets جست‌وجو را در سرور بخواند تا تخصص‌های پرجست‌وجو واقعی باشند؛ در غیر این صورت این بخش را حذف کنید، جای آن را پر نکنید با داده ساختگی.
