# پروفایل متخصص و رزرو — /providers/[id]

مسیر: `/providers/[id]`

## هدف
پروفایل عمومی متخصص و کل جریان رزرو (انتخاب خدمت، زمان، پرداخت) در یک صفحه.

## کاربر و زمینه
بدون نیاز به ورود برای مشاهده؛ برای رزرو نیاز به OTP.

## وابستگی API
GET /v1/providers/:id (شامل images.avatar/images.cover و rating.average/rating.count)، /services، /availability، GET /v1/providers/:id/portfolio (فاز C)، GET /v1/providers/:id/reviews (فاز D، عمومی، صفحه‌بندی‌شده)؛ POST /v1/bookings (Idempotency-Key)؛ joinWaitlist؛ POST /v1/media/:id/report برای گزارش تصویر نامناسب.

## فیلدهای واقعی داده
displayName، bio، city، specialties، verificationStatus؛ images.avatar/images.cover (url، width، height یا null)؛ rating.average (تهی وقتی count صفر)، rating.count؛ نمونه‌کار: id، caption، media.url/width/height، position (حداکثر ۴۰ مورد)؛ دیدگاه: id، rating (۱ تا ۵)، comment (اختیاری)، response.text/respondedAt (اختیاری)، createdAt — بدون هیچ فیلد هویتی از نویسنده؛ خدمات: name، durationMinutes، priceToman؛ زمان‌های آزاد: slot id، serviceId، startAt، endAt. saved: boolean | null روی خودِ متخصص و روی هر ردیفِ خدمت، جدا از هم (V3.2-C Story #9 — دیدنِ `38_WISHLIST.md`).

## چیدمان
سرآیند با تصویر پوشش (cover)، آواتار، نشان تأیید (یا رنگ خنثی وقتی هیچ‌کدام تنظیم نشده)، میانگین امتیاز + تعداد نظر کنار نام (یا «هنوز نظری ثبت نشده» وقتی count صفر است)، و دکمهٔ ذخیره/حذف علاقه‌مندی برایِ خودِ متخصص؛ همین دکمه، مستقل، کنارِ هر ردیفِ خدمت در فهرستِ خدمات هم تکرار می‌شود (V3.2-C Story #10)؛ نان‌ریزه؛ ستون چپ: نگارخانهٔ نمونه‌کار (شبکهٔ تصویر، تا ۴۰ مورد، هر مورد caption اختیاری) + خدمات + بلوک اعتبار + فهرست دیدگاه‌ها (تاریخ نسبی و خدمتِ رزروشده به‌جای هویت نویسنده؛ پاسخ متخصص زیرِ هر دیدگاه با نشانهٔ بصری متفاوت)؛ پنل چسبان راست: انتخاب خدمت → نوار روز → شبکهٔ زمان → خلاصه و پرداخت.

## اجزا
Breadcrumb، ServiceRow، DayStrip، TimeSlotPicker، PriceDisplay، Button، VerificationBadge، RatingSummary، ReviewCard

## حالت‌ها
بارگذاری اسکلتی برای خدمات، زمان‌ها و نگارخانه؛ خالی نگارخانه: «این متخصص هنوز نمونه‌کاری ثبت نکرده» بدون شکستن چیدمان دوستونهٔ سرآیند؛ خالی زمان: «این متخصص در حال حاضر زمان آزاد ندارد» + دکمهٔ پیوستن به لیست انتظار؛ خطا: ErrorState با تلاش دوباره؛ تعارض ۴۰۹ هنگام پرداخت: سه زمان جانشین، نه پیام خطای ساده.

## کنش‌ها
انتخاب خدمت → بارگذاری زمان‌های آن خدمت؛ انتخاب زمان → فعال شدن دکمهٔ پرداخت؛ پرداخت → /checkout/result؛ نبود زمان → پیوستن به لیست انتظار.

## قواعد واکنش‌گرایی
۳۹۰: پنل رزرو به نوار چسبان پایین با دکمهٔ «مشاهدهٔ زمان‌ها» تبدیل می‌شود؛ ۱۲۸۰: پنل چسبان کنار محتوا.

## قواعد راست‌به‌چپ و فارسی
ساعت‌ها در span جدا با direction: ltr تا معکوس نشوند؛ قیمت با جداکنندهٔ فارسی.

## دسترس‌پذیری
دکمهٔ هر زمان حداقل ۴۴px؛ برچسب صریح روی هر خدمت و زمان برای screen reader (نه فقط رنگ برای وضعیت رزروشده/آزاد).

## رفتار تعامل
انتخاب خدمت باید state کلاینت زمان انتخاب‌شده را ریست کند تا زمان نامعتبر برای خدمت قبلی باقی نماند.

## عناصر آینده/شکاف
نگارخانهٔ تصاویر — دیگر شکاف نیست، IMPLEMENTABLE NOW (فاز C). دیدگاه مشتریان، میانگین امتیاز و پاسخ متخصص — دیگر شکاف نیست، IMPLEMENTABLE NOW (فاز D)؛ اما PRODUCT DECISION REQUIRED روی نمایش نامِ نویسنده — پاسخ API عمداً هیچ هویتی ندارد (انتشار آن امکان بازسازی کل تاریخچهٔ رزرو یک مشتری را می‌دهد)، پس طرح باید با تاریخ نسبی و نام خدمت کار کند مگر تصمیم محصولی دیگری گرفته شود. نقشه و نشانی دقیق — BACKEND GAP (شهر بدون مختصات).
