## 3. Component and state inventory added this pass

Proto §25's twenty numbered state cards use the **same numbering as spec 45 §4**; the three
always-true cards (non-enumerating refusal, absent revoked-grant history, responsive behaviour) are
deliberately unnumbered because they hold across all twenty.

| Component | States |
|---|---|
| Roster row (grant-bearing) | loading · no-access · active-grant · granting · idempotent-result · revoking · not-grantable · removed-between-read-and-mutation · authority-lost |
| Member identity | professional-name label · phone-framed label · duplicate label separated by hint |
| Access badge | hollow ring (none) · filled circle (active) · square (practitioner-chat) |
| Grant interaction (no dialog) | idle · submitting (disabled, duplicate-proof) · announced success · failure + accessible retry |
| Revoke dialog (the screen's only dialog) | idle (checkbox unchecked) · armed · submitting · failed + retry |
| Workspace selector | loading · empty · single (hidden) · multi (none preselected) · one-removed |
| Workspace card | owner · delegated read-only · active · inactive · long-label truncated |
| Read-only banner | persistent, non-dismissible |
| Summary figure card | value · zero · loading · section-error |
| Settlement table/cards | page · empty · next-page · section-error |
| Ledger table | rows · empty · recorded-rate cell |
| Neutral refusal | one message, all causes |

## 4. Checks run, and checks not run

**Run:** local asset references (fonts, `support.js`) resolve; no duplicated element ids across the
three prototypes; every input and control in the new sections carries a visible label or accessible
name; the revoke dialog — the only dialog on either surface — wires `aria-labelledby` and
`aria-describedby`, and no confirmation step remains on the grant path; no relative link points at a
missing file; **no raw UUID literal, full phone number, email address, `workspaceRef`, `userId`,
`professionalId` or membership id is rendered anywhere**; no anonymous or session-local label
(«عضو نمونه», «فضای مالی ۱/۲/۳») survives in any current-state surface; no write control exists on
any `finance_read` surface; owner and grantee states differ by shape and text as well as colour; the
three viewport classes render without overflow; long Persian copy and ten-digit amounts do not break
the amount column; console load check on all three prototypes.

**NOT VERIFIED — static artifact:** real tab order, focus trap behaviour, focus return, computed
accessible-name output from an accessibility tree, screen-reader RTL reading order, live-region
announcement timing, measured contrast ratios per token pair, touch-target size at real device
pixel ratios, reduced-motion behaviour. These are implementation acceptance criteria. **No WCAG 2.1
AA conformance is claimed.**
