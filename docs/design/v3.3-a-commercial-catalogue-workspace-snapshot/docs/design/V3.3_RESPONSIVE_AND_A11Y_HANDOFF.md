# V3.3 — Responsive and accessibility handoff

**Applies to:** `Prototype - Customer.dc.html`, `Prototype - Pro and Admin.dc.html`, `Prototype - Admin Control Plane.dc.html`, `Prototype - Finance Workspace.dc.html`
**Revised:** 2026-09-12 (finance-read closure pass, corrected twice) · **Implementation baseline:** commit `5d4b3de5d7b386d14dc72c5bbd03f17fead64b38`

---

## 1. Breakpoints

| Name | Range | Primary target |
|---|---|---|
| Mobile | < 640px | 390 (design target), 375 and 412 as checkpoints |
| Tablet | 640–1023px | 768 portrait, 834 |
| Desktop | ≥ 1024px | 1280 (design target), 1440+ as fluid growth |

The V3 web app has **no width-based media queries and 500+ inline style objects**, so breakpoints
cannot be expressed in the current styling mechanism. This is a standing prerequisite, recorded in
`V3_DESIGN_SYSTEM.md`: either a stylesheet/CSS-module layer or a container-query-capable wrapper must
exist before any rule below can ship. The rules are written so they can be satisfied either by media
queries or by container queries without re-authoring the markup.

## 2. What changed in the prototypes

Every container added in this V3.3 work is now fluid rather than pinned: fixed `width: 1280px`,
`width: 700px`, `width: 420px` and `width: 390px` became `width: min(Npx, 100%)`, and fixed-column
grids (`repeat(4, 1fr)`, `repeat(3, 1fr)`, `1fr 1fr`, `1.1fr 1fr`, `1.2fr 1fr`) became
`repeat(auto-fit, minmax(…, 1fr))`. Appearance at ≥1280 is unchanged; below it the layout reflows
instead of overflowing.

**Deliberately unchanged:** the pre-V3.3 sections of the two older prototypes keep their fixed
artboard widths and their paired 390 mobile mockups. Those are canvas artboards showing two explicit
viewports, not responsive pages, and rewriting them would alter previously reviewed work. The rules
below still govern their implementation.

## 3. Per-pattern behaviour

### Wide tables (plan versions, price tiers, credit ledger, catalogue, enforcement routes, settlements)
- **Desktop:** full table, all columns.
- **Tablet:** table keeps its column set and its wrapper scrolls horizontally — `overflow-x: auto`
  on the card, with `min-width` on the table so columns never crush. The wrapper takes
  `tabindex="0"` and an accessible name so a keyboard user can scroll it.
- **Mobile:** the table becomes a card list, one card per row, label-above-value, preserving row
  order. Never a horizontally scrolling table on mobile. Columns that exist only for scanning
  (activation window, contract version) drop to a collapsible secondary line.
- The immutable credit ledger keeps **all three row kinds visible** at every width; nothing is
  hidden behind a filter, because the ledger is the record.

### Forms (plan version draft, collection-policy version, credit quantity, assignment reason)
- **Desktop:** two-column pairs where fields are genuinely related (min/max, start/end).
- **Tablet:** same pairs while each column stays ≥240px, otherwise single column.
- **Mobile:** always single column. Labels stay above inputs. The mandatory-reason textarea keeps
  ≥3 visible rows at every width.
- Related-bound pairs (percentage min/max, activation start/end) must break together, never leaving
  one half of a bound on a different row from its sibling.

### Navigation
- **Desktop:** persistent sidebar (pro/admin shells).
- **Tablet:** sidebar collapses to icons with visible labels on focus; content gets the width.
- **Mobile:** bottom tab bar per `25_MOBILE_NAVIGATION.md`; admin surfaces use a drawer, not a tab
  bar, because the admin destination set exceeds five.
- The workspace selector is a two-card row on desktop/tablet and a stacked list on mobile — it is
  never reduced to a dropdown that hides which workspace is active.

### Dialogs (plan change, publish, retire, activation refusal)
- **Desktop/Tablet:** centred, `max-width: 680px`, `max-height: 85vh`, body scrolls, header and
  action row pinned.
- **Mobile:** full-screen sheet; the action row pins to the bottom above the safe area; the
  consequence list scrolls, the actions do not.
- Destructive or irreversible actions keep their full consequence text at every width. **Consequence
  copy is never truncated, collapsed or moved behind a disclosure on small screens.**

### Cards and stat grids
- `repeat(auto-fit, minmax(200–320px, 1fr))` throughout: 4-up desktop, 2-up tablet, 1-up mobile,
  with no orphan single card on a row of its own at tablet where 2-up is achievable.

### The dense control page (Control Plane §02)
- **Desktop:** two columns — commands beside activation/kill switch.
- **Tablet:** single column, order preserved: status → preview → transitions/exemptions → activation
  → kill switch.
- **Mobile:** same order; the aggregate preview becomes a three-row list rather than three cards;
  the kill switch stays last and keeps its full-width 48px target.
- The kill switch is never placed adjacent to another destructive control at any width.

### Amounts and disclosure (Customer §21)
- The three-amount block is a two-column definition list on desktop and tablet and stays a
  two-column list on mobile (label start, figure end) — amounts must remain scannable as a column.
- The ten-row disclosure list never hides a row at any width. On mobile each row wraps to two lines
  (label, then value + status badge) rather than truncating.

## 4. Accessibility — verified in the design

- **Status never by colour alone.** Every badge carries a distinct shape (filled circle, square,
  rounded square, dashed ring, outlined circle) plus its Persian text.
- **Targets ≥44px** on every button, input, textarea, radio and checkbox row added this pass; the
  kill switch and primary confirmations are 48px.
- **Contrast:** full-opacity ink on tinted grounds; no alpha-muted or `color-mix` body text. Faint
  `oklch(0.58 0.015 330)` is used only for labels and captions at ≥12px, never as the only copy of a
  consequence.
- **Semantics:** `<dl>` for the disclosure and amount blocks; real `<table>` with `<caption>` and
  `<thead>`; `<fieldset>`/`<legend>` for collection mode and deposit rule; `role="dialog"` +
  `aria-modal` + `aria-labelledby` on dialogs; `role="alert"` on the activation refusal;
  `role="note"` + `aria-labelledby` on the design-review annotation frame.
- **Disabled controls state their reason in adjacent text**, and the disabled policy-acceptance
  checkbox points at that text with `aria-describedby`. No tooltip-only explanations.
- **RTL:** `dir="rtl"` containers, logical properties (`padding-inline-start`, `text-align: start`),
  and `dir="ltr"` + `unicode-bidi: isolate` on keys, references and code so mixed runs read correctly.
- **Non-enumerating refusals:** every refusal renders the single shared sentence with no cause,
  count or distinction, matching the server.

## 5. Accessibility — requires testing at frontend implementation, NOT claimed as PASS

- Tab order through every form, dialog and table in a real DOM.
- Focus trap inside each dialog while open.
- Focus return to the invoking control after a dialog closes.
- Accessible name of every control as computed by a real accessibility tree.
- Screen-reader reading order in RTL, including mixed LTR key and code runs.
- Live-region announcement of saving, saved and refused transitions.
- Measured contrast ratios with a tool, per token pair, at final rendered sizes.
- Keyboard operation of the quantity input, deposit-rule fieldset and collection-mode radio group.
- Touch-target size at real device pixel ratios.
- `prefers-reduced-motion` once any transition exists.

**No WCAG 2.1 AA conformance is claimed.** These prototypes are static design artifacts; the items
in §5 are acceptance criteria for implementation, not results.

## 6. #149a / #152 finance surfaces (added 2026-09-12)

Same three breakpoints. The smallest reusable pattern was applied rather than a redesign of earlier
sections: fluid containers (`width: min(Npx, 100%)`), `repeat(auto-fit, minmax(…, 1fr))` grids, and
`overflow-x: auto` wrappers with `min-width` tables where a table must stay a table.

### Owner roster with grant/revoke (Pro §25)

- **Desktop** — structured rows: `displayLabel`, the four-digit identification hint, membership role,
  status, access badge, one action.
- **Tablet** — label, hint, role and status all preserved; the action is not compressed into an icon.
- **Mobile** — one card per member; label and hint stay on separate lines; the action is full-width
  and separated from bottom navigation.
- Confirmation dialogs become full-screen sheets; the action row pins above the safe area and the
  consequence text scrolls rather than truncating. **Only revocation has a dialog** — granting is
  reversible and submits immediately from the row's own button at every width.
- **Grant and Revoke are never adjacent at any width.** A row is in exactly one state and therefore
  carries exactly one of the two buttons — structural, not a spacing rule.

### Finance workspace (`/finance`, §F0–F5)

- **Desktop** — selector beside the content hierarchy; settlement and ledger stay tables.
- **Tablet** — selector stays visible above the content; sections stack in a fixed order.
- **Mobile** — workspace cards first, then the selected workspace summary; wide tables become
  labelled card rows, never horizontally scrolling financial tables.
- Amount columns stay visually aligned at every width (tabular numerals, end-aligned).
- Cursor pagination stays reachable and keyboard operable; there is no page number or total count
  because the server returns neither.
- The per-order ledger is the one table kept scrollable on narrow widths; its wrapper takes
  `tabindex="0"` and an accessible name so a keyboard user can reach it.
- A single-workspace user sees no selector at any width.
- Workspace titles carry the server's `displayLabel`; a long Persian name wraps then truncates
  visually while the full label stays available to assistive technology and on hover.

### Accessibility verified in these two surfaces

`fieldset`/`legend` around workspace selection with real radio inputs · ≥44px targets on every
control · status by text **and** shape (hollow ring, filled circle, square, hollow square) ·
`role="dialog"` + `aria-modal` + `aria-labelledby` + `aria-describedby` on the revoke confirmation
dialog, the only dialog in either surface · `role="status"` + `aria-live="polite"` on grant and
revoke progress/result, with the member named in the announcement · a failed mutation exposes a
retry control tied to its error by `aria-describedby` · `role="alert"` on the access-revoked refusal · `role="note"` on design-review annotations
· real `<table>` with `<caption>` and `<thead>` · `dir="ltr"` isolation on references, code **and
every four-digit identification hint**, so a masked hint is neither reordered nor visually corrupted
in an RTL line · each grant/revoke action's accessible name carries label **and** hint, so two
members sharing a display name are never announced identically and the hint is never the sole
accessible name · each confirmation dialog repeats the exact identity of the row it acts on ·
disabled reasons stated in adjacent text · no disabled write controls on a read-only surface.

### Requires testing at frontend implementation — NOT claimed as PASS

Tab order · focus trap in each dialog · focus return to the invoking control · computed accessible
names from a real accessibility tree · keyboard operation of the workspace selector · live-region
announcement of grant/revoke progress and result, of workspace switching, and of access revocation ·
screen-reader RTL reading order with isolated LTR reference runs · measured contrast per token pair ·
touch-target size at real device pixel ratios · `prefers-reduced-motion`.
