# حریم خصوصی و داده‌های من — /account/privacy

مسیر: `/account/privacy` (هنوز در apps/web ساخته نشده — فاز E، UI REQUIRED)

## هدف
یک صفحه، دو کنش غیرقابل‌بازگشت‌نما: گرفتن خروجیِ کامل داده‌ها، و درخواستِ حذف حساب با پنجرهٔ هفت‌روزهٔ قابل‌لغو.

## کاربر و زمینه
نیاز به ورود. بدون پارامتر کاربر در هیچ درخواست — سرور موضوع را از نشست تعیین می‌کند؛ «حذف داده‌های شخص دیگر» درخواستی است که این API نمی‌تواند بیان کند.

## وابستگی API
GET /v1/privacy/requests (فهرست همهٔ درخواست‌های خودم)؛ POST /v1/privacy/export (۲۰۲)؛ GET /v1/privacy/export/:id (وضعیت)؛ GET /v1/privacy/export/:id/download؛ POST /v1/privacy/deletion با `{confirm: 'DELETE'}` (۲۰۲)؛ POST /v1/privacy/deletion/:id/cancel.

## فیلدهای واقعی داده
id، kind (`export`|`erasure`)، status (`pending`|`processing`|`ready`|`expired`|`failed`|`cancelled`|`completed`)، requestedAt، executeAfter (فقط حذف)، expiresAt (فقط خروجی)، completedAt، cancelledAt، failureCode. سند خروجی: `sections` (کلید `moduleKey.sectionKey`، هرکدام با `description` فارسی)، `retained` (فهرست `{module, table, reason}`).

## چیدمان
دو کارتِ مجزا زیر هم، هرکدام با تیترِ صریح: «دریافت خروجیِ داده‌ها» و «حذف حساب». هیچ اشتراکِ عنصر بینشان — دو تصمیمِ متفاوت با دو وزنِ متفاوت.

### کارتِ خروجی
وضعیتِ فعلی (اگر درخواستی باز است) + دکمهٔ درخواستِ تازه (غیرفعال اگر یک درخواستِ باز موجود است، با پیامِ «درخواستِ شما در حال آماده‌سازی است»). وقتی `ready`: دکمهٔ «دانلود» + متنِ صریحِ «تا [تاریخ] در دسترس است». وقتی `expired`: «فایل شما دیگر در دسترس نیست» + دکمهٔ درخواستِ تازه — این یک پایانِ عادی است، نه خطا.

### کارتِ حذف
اگر درخواستی باز نیست: توضیحِ کوتاه از پنجرهٔ هفت‌روزه + چه‌چیزی باقی می‌ماند (سابقهٔ مالی، به‌دلیلِ قانونی) + دکمهٔ شروع. کلیک → دیالوگِ تأیید با فیلدِ متنی که کاربر باید عیناً `DELETE` تایپ کند (نه ترجمه‌شده). اگر درخواستی باز است: نمایشِ شمارشِ معکوس تا `executeAfter` (طرّاحی‌شده به‌صورتِ تاریخ + روزهای باقی‌مانده، نه ساعت‌شمار زنده) + دکمهٔ «لغو درخواستِ حذف».

## اجزا
Card، Button، Alert (info/success/error)، ConfirmDialog با فیلدِ متنیِ تأیید، Badge برای وضعیت.

## حالت‌ها
`pending`/`processing`: «در حالِ آماده‌سازیِ داده‌های شما» بدون دکمهٔ دانلود (دو وضعیت از دیدِ کاربر یکسان‌اند). `ready`: دانلود + تاریخِ انقضا. `expired`: پایانِ عادی، دکمهٔ درخواستِ تازه. `failed`: «مشکلی پیش آمد» + دکمهٔ تلاشِ دوباره. تعارضِ ۴۰۹ (درخواستِ بازِ دیگری از همان نوع): پیامِ سرور مستقیماً نمایش داده می‌شود، دکمهٔ ساخت غیرفعال می‌شود و درخواستِ موجود به‌جایش نشان داده می‌شود. بارگذاریِ اسکلتی برای فهرستِ اولیه.

## کنش‌ها
درخواستِ خروجی → دانلود (JSON، ساخته‌شده در کلاینت، بدون لینکِ امضاشده) → مشاهدهٔ `retained` به‌صورتِ فهرستِ متنی («سابقهٔ پرداخت شما نگه داشته می‌شود چون قانوناً الزامی است») نه فقط JSONِ خام؛ درخواستِ حذف → تایپِ `DELETE` → مشاهدهٔ شمارش → لغو (در هر لحظه تا اجرا) یا انتظار تا اجرا.

## قواعد واکنش‌گرایی
۳۹۰: دو کارت تمام‌عرض زیر هم، دیالوگِ تأیید تمام‌صفحه؛ ۱۲۸۰: دو کارت در عرضِ محدود (حداکثر ۦ۶۴۰ پیکسل)، بدون گرید کنارِ‌هم — این دو تصمیم را نباید در کنارِ هم به‌چشمِ مقایسه‌پذیر نشان داد.

## قواعد راست‌به‌چپ و فارسی
تاریخ‌ها شمسی با اعدادِ فارسی؛ رشتهٔ تأییدِ `DELETE` لاتین و `direction: ltr` می‌ماند — عمداً ترجمه نشده، دقیقاً همان‌طور که کاربر باید تایپ کند.

## دسترس‌پذیری
دیالوگِ تأیید با تله‌ی فوکوس؛ وضعیت‌های `ready`/`expired`/`failed` با `role=status`؛ فیلدِ تأییدِ حذف با برچسبِ صریح («برای تأیید، عبارتِ DELETE را تایپ کنید»)، نه فقط placeholder.

## رفتار تعامل
«این قابلِ‌بازگشت نیست» هرگز روی صفحهٔ تأیید نوشته نمی‌شود — برعکسِ واقعیت است؛ به‌جایش تاریخِ دقیقِ اجرا و دکمهٔ لغو تا آن لحظه. حساب در تمامِ پنجره کاملاً قابلِ‌استفاده می‌ماند؛ هیچ بنر یا غیرفعال‌سازی‌ای این را نباید نقض کند. پس از اجرا هیچ صفحه‌ای برای این کاربر وجود ندارد — نشست باطل و شماره دیگر قابلِ ورود نیست؛ آخرین چیزی که پیش از اجرا می‌بیند همین صفحه با شمارشِ روبه‌پایان است، طرّاحیِ آن صفحه پایانی مهم است.

## عناصر آینده/شکاف
هیچ اعلانِ ایمیل/پیامک برای این رویدادها — فقط درون‌برنامه‌ای، دستهٔ اجباری («privacy») و غیرقابلِ‌خاموش‌کردن. دانلودِ مجددِ خروجیِ منقضی‌شده وجود ندارد — درخواستِ تازه. صادرات/حذفِ داده برای متخصص یا کسب‌وکار (نه فقط مشتری) — BUSINESS DECISION REQUIRED، بک‌اند فعلاً فقط `subjectUserId` را می‌شناسد نه نقش.

## یادداشت پیاده‌سازی
API کامل و آزموده (۳۱ مورد در `privacy.pg-spec.ts`). یک پیامِ ۴۰۴ واحد («NOT_FOUND_OR_NOT_YOURS») برای چهار وضعیتِ متفاوت (متعلق به دیگری، ناموجود، هنوز آماده نشده، منقضی) — رابط کاربری نباید دلیلِ دقیق‌تری اختراع کند؛ همان پیامِ سرور را نشان دهید.
