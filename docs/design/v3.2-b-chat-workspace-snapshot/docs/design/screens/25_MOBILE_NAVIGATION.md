# ناوبری موبایل — تصمیم یکپارچه در چهار بستر

منبع کامل: `V3_INFORMATION_ARCHITECTURE.md`. این سند فقط الگوی مشترک را یک‌جا جمع می‌کند تا Claude Code یک مکانیزم بسازد، نه چهار مکانیزم جدا.

## الگوی مشترک

یک جزء واحد — `MobileTabBar` — با ظاهر یکسان (ارتفاع ۵۶، سایهٔ `bar`، حداکثر پنج مقصد، `aria-current` روی فعال) در هر چهار بستر استفاده می‌شود. تفاوت بسترها فقط در **کدام مقصدها** روی نوار می‌نشینند، نه در جزء.

| بستر | نوار پایین (حداکثر پنج) | باقی مقصدها |
| --- | --- | --- |
| مشتری | خانه، جست‌وجو، رزروها، باشگاه، حساب | زیر «حساب»: لیست انتظار، کسب‌وکار، حالت متخصص، خروج |
| متخصص | امروز، رزروها | باقی هفت مقصد در یک برگهٔ کشویی از دکمهٔ منو |
| کسب‌وکار | همان الگوی متخصص (پوستهٔ مشترک) | — |
| مدیریت | بدون نوار پایین — عملیات مدیریتی روی موبایل کم‌بسامد است؛ نوار افقیِ تیره با اسکرول افقی به‌جای نوار پایین | — |

## چرا این تفکیک

مشتری روزی چند بار به این پنج مقصد سر می‌زند — نوار پایین برای دسترسی فوری توجیه دارد. متخصص در موبایل بیشتر «امروز» و «رزروها» را می‌بیند؛ بقیه (زمان‌های آزاد، خدمات، مالی، آمار، پروفایل) کارهای دسکتاپ‌محورترند و در برگهٔ کشویی کافی است. مدیریت اساساً یک ابزار دسکتاپی است؛ ساختن نوار پایین برایش کاری می‌سازد که استفادهٔ واقعی ندارد.

## پیش‌نیاز فنی

هیچ‌کدام از این‌ها بدون مکانیزم CSS شرطی بر اساس عرض (که امروز در محصول صفر است) قابل ساخت نیست — این تصمیم صرفاً چیدمان را نام می‌برد؛ ساختن خودِ مکانیزم رسانه‌ای، پیش‌نیاز Claude Code است (نگاه کنید به بخش ۲ سند نهایی).
