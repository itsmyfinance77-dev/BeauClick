# رزروهای متخصص — /pro/bookings

مسیر: `/pro/bookings`

## هدف
مدیریت کامل چرخهٔ نوبت: مشاهده، تکمیل، عدم حضور، جابه‌جایی. بزرگ‌ترین صفحهٔ محصول.

## کاربر و زمینه
نیاز به نقش bc_provider.

## وابستگی API
listProfessionalBookings، completeBooking، markNoShow، rescheduleBooking، bookingHistory، listMyServices، listMySlots

## فیلدهای واقعی داده
id، status، startAt، endAt، rescheduleCount، cancellationReason، تاریخچهٔ وضعیت، commissionRateBp، سطح باشگاه مشتری.

## چیدمان
برگهٔ tablist واقعی: پیش‌رو / گذشته؛ فهرست گروه‌بندی‌شده بر اساس روز؛ هر ردیف با دکمه‌های کنش پشت ConfirmDialog.

## اجزا
SegmentedControl یا tablist، BookingRow، AuditTrail، ConfirmDialog

## حالت‌ها
بارگذاری اسکلتی ردیف؛ خالی هر برگه جدا؛ خطا با تلاش دوباره.

## کنش‌ها
تکمیل نوبت، ثبت عدم حضور، جابه‌جایی — هر سه پشت تأیید با متن پیامد؛ منطق و قواعد این تصمیم‌ها دست‌نخورده می‌ماند، فقط ظاهر تغییر می‌کند.

## قواعد واکنش‌گرایی
۳۹۰: هر ردیف کارت عمودی با دکمه‌های تمام‌عرض؛ ۱۲۸۰: ردیف جدولی فشرده‌تر با دکمه در انتها.

## قواعد راست‌به‌چپ و فارسی
تاریخ/ساعت جلالی و LTR جزئی مشابه سایر صفحات.

## دسترس‌پذیری
tablist واقعی با role و aria-selected صحیح (تنها جای محصول با tablist واقعی)؛ ConfirmDialog نیاز به aria-describedby برای متن پیامد (امروز ندارد).

## رفتار تعامل
برگهٔ «لغوشده» امروز داده دارد ولی فیلتر جدا ندارد — باید اضافه شود (طبقهٔ ب، بدون تغییر سرور).

## عناصر آینده/شکاف
نام و شماره مشتری — BACKEND GAP همان مورد صفحهٔ /pro. جست‌وجوی مشتری در فهرست رزروها — وابستهٔ پارامتر تازهٔ سرور.

## یادداشت پیاده‌سازی
588 خط، بزرگ‌ترین صفحهٔ محصول. اولویت پیاده‌سازی: گروه‌بندی بر اساس روز و تفکیک برگهٔ لغوشده قابل انجام بدون تغییر سرور.
