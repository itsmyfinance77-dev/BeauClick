# V3_COMPONENT_INVENTORY

BeauClick V3.1 — فهرست اجزا
سند طراحی. هیچ جزئی در کد تغییر نکرده است.

مرجع: `v3/apps/web/components/ui.tsx`، `v3/apps/web/components/kit.tsx`، `app-shell.tsx`، `pro-shell.tsx`، `admin-shell.tsx`

---

## ۱. آنچه امروز هست

`ui.tsx` — پایه: `Button`، `Input`، `Textarea`، `Select`، `Card`، `Alert`، `Label`، `FieldHint`
`kit.tsx` — ترکیبی: `NavLink`، `ContextBand`، `PageHeader`، `StatCard`، `StatGrid`، `Badge`، `EmptyState`، `SegmentedControl`، `Chip`
پوسته‌ها: `AppShell`، `ProShell`، `AdminShell`

فهرست کوتاهی است و برای محصولی با این وسعت، بیش از حد کوتاه. نتیجه‌اش این است که هر صفحه اجزای خودش را با `div` و `style` درجا می‌سازد — کارتِ رزرو در `bookings`، کارتِ نتیجه در `search` و سطرِ زمان در `availability` هیچ‌کدام جزء نیستند.

---

## ۲. حکمِ هر جزء

`نگه‌داشتن` بدون تغییر · `بازطراحی` همان API، ظاهرِ نو · `استخراج` امروز درجا نوشته می‌شود، باید جزء شود · `جدید` وجود ندارد · `جانشینی` باید با چیزِ دیگری عوض شود

### پایه

| جزء | حکم | یادداشت |
| --- | --- | --- |
| `Button` | بازطراحی | افزودنِ گونهٔ `tertiary`؛ چهار اندازه (۵۴/۴۶/۴۲/۴۰)؛ `fullWidth` فقط با درخواستِ صریح، نه پیش‌فرضِ فرم |

## ۳. آنچه ساخته نمی‌شود

| جزء | دلیل |
| --- | --- |
| `Rating` | سیستمِ دیدگاه وجود ندارد. جای‌اش در پروفایل نگه داشته شده، خودش ساخته نمی‌شود. |
| `DatePicker` / `TimePicker` سفارشی | `input type=date/time` بومی با تقویم جلالیِ مرورگرِ فارسی کار می‌کند و امروز هم همین است. ساختنِ تقویمِ جلالیِ سفارشی هزینهٔ بزرگی است با سودِ کم. |
| `Toast` | امروز پیام‌ها درجای صفحه‌اند و این برای عملیاتِ برگشت‌ناپذیر بهتر است. |
| `Tabs` جدا از `SegmentedControl` | یک الگو کافی است. |
| `IconButton` به‌عنوان جزءِ عمومی | مجموعهٔ نمادی در مخزن نیست؛ تا آن زمان دکمهٔ فقط-نماد موردی می‌ماند. |
| `Dialog` / `ConfirmDialog` | **موجود و کارآمد.** منطقِ تأییدِ `pro/bookings` دست‌نخورده می‌ماند؛ فقط توکنِ ظاهری می‌گیرد. |
| `Avatar` تصویری | خط لولهٔ رسانه (فاز C) نیست. جای‌نگهدارِ راه‌راه استفاده می‌شود. |

## ۴. شمارش

| حکم | تعداد |
| --- | --- |
| نگه‌داشتن | ۵ |
| بازطراحی | ۱۵ |
| استخراج | ۱۱ |
| جدید | ۱۲ |
| جانشینی | ۱ |
| ساخته نمی‌شود | ۷ |

از ۱۲ جزءِ جدید، ۹ موردش در نمونه‌های بصری دیده می‌شود؛ سه موردِ دیگر (`Skeleton`، `ErrorState`، `Pagination`) حالت‌اند و در سند توصیف شده‌اند.

بیشترین کارِ واقعی «استخراج» است، نه «جدید»: یازده الگو امروز در محصول وجود دارند و در چند صفحه تکرار شده‌اند بدون آن‌که جزء باشند. این توضیح می‌دهد چرا کارتِ رزرو در بستر مشتری و بستر متخصص دو چیزِ متفاوت‌اند.
